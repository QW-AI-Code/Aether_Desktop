## تازه‌های نسخهٔ ویندوز ۱.۳.۰

نسخهٔ برنامه همچنان <bdi>1.4.0</bdi> است. این انتشار سه قابلیت را از <bdi>Aether</bdi> اندروید نسخهٔ <bdi>1.5.0</bdi> به ویندوز می‌آورد — **کانفیگ‌های سفارشی**، **ورود <bdi>Zero Trust</bdi>** و **اشتراک بازطراحی‌شده روی شبکهٔ محلی** — با همان رفتار و همان متن‌های گوشی، و هستهٔ **دست‌نخوردهٔ <bdi>Aether Core 2.4.0</bdi>** را همراه دارد. حالت «هات‌اسپات گوشی» اندروید عمداً در نسخهٔ ویندوز **نیست**. پروفایل‌های ذخیره‌شده و بک‌اند انتخابی حفظ می‌شوند.

### کانفیگ‌های سفارشی (تازه، پیش‌فرض خاموش)

از <bdi>Aether</bdi> اندروید نسخهٔ <bdi>1.5.0</bdi> آورده شده: **تنظیمات ← «کانفیگ‌های سفارشی»**. تا وقتی کلیدش خاموش است (پیش‌فرض) **هیچ چیز عوض نمی‌شود**: شش حالت قبلی، پروفایل‌ها و موتور دقیقاً مثل قبل کار می‌کنند.

* **چه چیزی وارد می‌شود:** لینک‌های <span dir="ltr">`vless://`</span>، <span dir="ltr">`vmess://`</span>، <span dir="ltr">`trojan://`</span>، <span dir="ltr">`ss://`</span>، <span dir="ltr">`socks://`</span> / <span dir="ltr">`socks5://`</span>، <span dir="ltr">`wireguard://`</span> / <span dir="ltr">`wg://`</span>؛ کانفیگ کامل <bdi>Xray JSON</bdi> (هر خروجی‌ای که <bdi>Xray</bdi> پشتیبانی کند، مثل <bdi>Hysteria2</bdi>، <bdi>XHTTP</bdi>، <bdi>Reality</bdi>)؛ متن اشتراک ساده یا <bdi>Base64</bdi>؛ **لینک اشتراک** (فقط <span dir="ltr">`https://`</span>، حداکثر ۵ تغییر مسیر، ۲ مگابایت، ۲۰ ثانیه؛ وقتی وصل هستید از داخل تونل گرفته می‌شود)؛ و **فایل‌های <span dir="ltr">`.npvt`</span>** برنامهٔ <bdi>NapsternetV / Npv Tunnel</bdi>.
* **روش وارد کردن:** چسباندن در کادر و زدن «وارد کردن»، انتخاب فایل، یا کشیدن و رها کردن فایل. **خواندن محلی <bdi>QR</bdi> از تصویر PNG/JPEG/WebP پشتیبانی می‌شود**؛ دوربین لازم نیست و تصویر به سرور فرستاده نمی‌شود. چسباندن URL اشتراک HTTPS، اشتراک قابل‌به‌روزرسانی ذخیره می‌کند.
* **قفل فایل <span dir="ltr">`.npvt`</span> رعایت می‌شود:** فایل بایت‌به‌بایت مثل اندروید باز می‌شود. کانفیگی که به دستگاه دیگری قفل است، منقضی شده یا «فقط موبایل» است با دلیل روشن رد می‌شود؛ فایل رمزدار رمزش را می‌پرسد. لینک خام کانفیگ قفل‌دار هرگز نمایش، کپی یا ویرایش نمی‌شود.
* **فهرست ذخیره‌شده:** انتخاب، تغییر نام، ویرایش (فقط بدون قفل)، کپی لینک، حذف و دکمهٔ جداگانهٔ «حذف همهٔ کانفیگ‌ها». فهرست با <bdi>Windows DPAPI</bdi> رمز می‌شود (<span dir="ltr">`custom_configs.bin`</span>) و رابط وب هرگز خروجی خام را نمی‌بیند.
* **۱۵ حالت زنجیره:** کانفیگ تنها، جلوی موتورها یا پشت آن‌ها:
  * <span dir="ltr">`Config`</span>
  * <span dir="ltr">`Config → Aether`</span>، <span dir="ltr">`Aether → Config`</span>
  * <span dir="ltr">`Config → Psiphon`</span>، <span dir="ltr">`Psiphon → Config`</span>
  * <span dir="ltr">`Config → Tor`</span>، <span dir="ltr">`Tor → Config`</span>
  * <span dir="ltr">`Config → Aether → Psiphon`</span>، <span dir="ltr">`Config → Aether → Tor`</span>، <span dir="ltr">`Config → Tor → Psiphon`</span>، <span dir="ltr">`Config → Tor → Aether`</span>
  * <span dir="ltr">`Aether → Psiphon → Config`</span>، <span dir="ltr">`Aether → Tor → Config`</span>، <span dir="ltr">`Tor → Psiphon → Config`</span>، <span dir="ltr">`Tor → Aether → Config`</span>
* **کارت اتصال:** کاشی پروتکل زنجیرهٔ واقعی را نشان می‌دهد، مثلاً <span dir="ltr">`VLESS → Tor`</span> یا <span dir="ltr">`Tor → Psiphon → Trojan`</span>، و برای جا شدن کوتاه می‌شود.
* **هستهٔ <bdi>Xray v25.12.8</bdi>:** به‌صورت <span dir="ltr">`engine\xray\xray.exe`</span> همراه است (فایل zip و باینری هر دو معماری <bdi>x64/x86</bdi> با هش <bdi>SHA-256</bdi> در <span dir="ltr">`scripts/stage-xray.ps1`</span> پین شده‌اند). نسخهٔ ۲۶ کلیدهای <span dir="ltr">`allowInsecure`</span> و <span dir="ltr">`seed`</span> در <bdi>mKCP</bdi> را رد می‌کند که هنوز در بسیاری از کانفیگ‌ها و فایل‌های قدیمی <span dir="ltr">`.npvt`</span> وجود دارد؛ به همین دلیل مانند اندروید روی نسخهٔ ۲۵.۱۲.۸ می‌ماند.
* **رفع گیر <span dir="ltr">`Config → Tor`</span>:** با روشن بودن <bdi>sniffing</bdi>، هستهٔ <bdi>Xray</bdi> مقصد هر اتصال را با <bdi>SNI</bdi> داخل <bdi>TLS</bdi> عوض می‌کرد. دست‌دادن تور <bdi>SNI</bdi> ساختگی (<span dir="ltr">`www.<random>.com`</span>) دارد، پس هر اتصال به نگهبان به جست‌وجوی نامی ناموجود تبدیل می‌شد و تور روی ۹۳٪ می‌ماند. حالا <bdi>sniffing</bdi> در همهٔ کانفیگ‌های ساخته‌شده خاموش است و آزمون‌ها آن را قفل می‌کنند.
* **امنیت:** هستهٔ <bdi>Xray</bdi> پنهان و داخل <bdi>Job Object</bdi> برنامه اجرا می‌شود (با بسته شدن برنامه بسته می‌شود)، فقط روی <bdi>loopback</bdi> گوش می‌دهد، فایل کانفیگ آن با توقف پاک می‌شود و حداکثر ۵ بار دوباره راه‌اندازی می‌شود. <bdi>DNS</bdi> داخل تونل می‌ماند؛ وقتی <bdi>Xray</bdi> از دل موتور یا تور ارتباط می‌گیرد نام سرور حل‌نشده فرستاده می‌شود. گارد نشت فقط وقتی کانفیگ سفارشی در حال اجراست راه خروجی اضافهٔ لازم را باز می‌کند. تونل‌زنی جزئی به‌طور پیش‌فرض خاموش و <bdi>MTU</bdi> پیش‌فرض ۱۲۸۰ باقی می‌ماند.

### کانفیگ‌های سفارشی: رفع زنجیره و پینگ (۱.۳.۰)

* **<span dir="ltr">`Config → Psiphon`</span> حالا واقعاً از کانفیگ رد می‌شود:** سایفون بدون <bdi>upstream</bdi> اجرا می‌شد و مستقیم وصل می‌شد. حالا پورت <bdi>SOCKS</bdi> محلی کانفیگ (<bdi>AETHER_UPSTREAM</bdi>) به آن داده می‌شود و در لاگ عبارت <span dir="ltr">`psiphon dials out through the upstream proxy`</span> دیده می‌شود.
* **خطای <span dir="ltr">`WSAEACCES (10013)`</span> سایفون:** در حالت <span dir="ltr">`Psiphon → Config`</span> قانون‌های فایروال جامانده از اجرای قبلی پاک می‌شوند و فیلتر خروجی به هاپ سایفون/<bdi>Xray</bdi> اجازه می‌دهد. اگر ویندوز باز هم دسترسی را رد کند، یک بار در لاگ نوشته می‌شود کدام قانون یا پروفایل (<bdi>BlockOutbound</bdi>) جلوی آن را گرفته است.
* **برچسب درست مسیر:** لاگ زنجیرهٔ واقعی را نشان می‌دهد، مثلاً <span dir="ltr">`Pipeline: Config → Psiphon (custom config chain)`</span>.
* **هاپ‌های کند:** زمان‌بندی <bdi>Xray</bdi> در زنجیره: دست‌دادن ۳۰ ثانیه، بیکاری ۱۸۰۰ ثانیه، <bdi>uplink</bdi> ۱۰ ثانیه و <bdi>downlink</bdi> ۳۰ ثانیه. وقتی کانفیگ خروجیِ پشت تور/سایفون است <bdi>Mux</bdi> با ۸ جریان روشن می‌شود؛ برای <bdi>XTLS Vision</bdi>، <bdi>WireGuard</bdi> و <bdi>Hysteria</bdi> هرگز فعال نمی‌شود.
* **پینگ واقعی:** هر کانفیگ دکمهٔ **پینگ** دارد و فهرست دکمهٔ **تست همه**. کانفیگ در یک <bdi>Xray</bdi> موقت فقط روی <bdi>loopback</bdi> (با <bdi>SOCKS</bdi> رمزدار، تا ۳۲ کانفیگ در هر اجرا) اجرا و <bdi>generate_204</bdi> دریافت می‌شود. نتیجه: تأخیر به میلی‌ثانیه، یا <bdi>-1</bdi> با برچسب‌های «بدون پاسخ»، «سرور خاموش»، «فیلتر شده»، «کانفیگ نامعتبر» یا «بدون شبکه».
* **پینگ عیب‌یابی:** بررسی‌های <bdi>DoH/TLS</bdi> همیشه گواهی **و** نام میزبان را تأیید می‌کنند.
* **حریم خصوصی لاگ:** نشانی سرور، نام میزبان، <bdi>IPv6</bdi> و <bdi>UUID</bdi> در خروجی <bdi>Xray</bdi> ماسک می‌شوند. اشتراک‌ها هنگام اتصال از داخل تونل دریافت می‌شوند.
* **چسباندن تمیز:** نویسه‌های نامرئی (<bdi>RLM/LRM</bdi>، <bdi>BOM</bdi>، نشانه‌های جهت، فاصلهٔ نشکن) که پیام‌رسان‌ها به لینک اضافه می‌کنند هنگام چسباندن، وارد کردن و دریافت اشتراک حذف می‌شوند.
* **باقی‌ماندهٔ ۱.۲.۵:** اسکریپت <span dir="ltr">`scripts/clean-legacy-1.2.5.py`</span> فایل‌های اضافی نسخهٔ ۱.۲.۵ را پاک می‌کند و <bdi>CI</bdi> آن را پیش از بررسی دست‌نخوردگی هسته اجرا می‌کند.

### ورود <bdi>Zero Trust</bdi> پیش از اتصال

* **اول وارد شوید:** در تنظیمات ← <bdi>Zero Trust</bdi> ← «کد ایمیلی»، دکمهٔ «ورود» پنجره‌ای باز می‌کند: کد به ایمیل فرستاده می‌شود، آن را وارد می‌کنید (سه بار فرصت)، پس از ۳۰ ثانیه «ارسال کد تازه» فعال می‌شود و هر مشکل (تیم یا ایمیل نادرست، کد اشتباه یا منقضی، نبود اینترنت) به زبان ساده توضیح داده می‌شود.
* **رمزشده و قابل مشاهده:** ورود با <bdi>Windows DPAPI</bdi> رمز می‌شود، به تیم **و** ایمیل گره می‌خورد و پنل نشان می‌دهد هنوز معتبر است یا نه و تا چه تاریخی اعتبار دارد. گزینهٔ «فراموش کردن این ورود» آن را پاک می‌کند. توکن هرگز به رابط وب نمی‌رسد.
* **کد هنگام اتصال:** اگر موتور وسط اتصال کد ایمیلی بخواهد، پنجره‌ای روی هر صفحه‌ای باز می‌شود. انتخاب «حالا نه» همان تلاش اتصال را متوقف می‌کند و آن را معطل نمی‌گذارد.
* **عضویت دستگاه:** دستگاه عضوشده وضعیت عضویتش را می‌بیند و با «حذف عضویت این دستگاه» (با تأیید و فقط وقتی قطع است) آن را برمی‌دارد؛ در اتصال بعدی دوباره عضو می‌شود.
* **توکن سرویس و توکن عضویت:** در بخش «توکن سرویس»، دکمهٔ «آزمایش توکن سرویس» همان مبادلهٔ موتور را بدون ذخیرهٔ چیزی اجرا می‌کند. «توکن دسترسی» (توکن عضویت) چسبانده‌شده همان لحظه بررسی می‌شود (خالی، نامعتبر، منقضی یا معتبر با زمان باقی‌مانده).

### اشتراک <bdi>VPN</bdi> روی شبکهٔ محلی

* **صفحهٔ «اشتراک» بازطراحی شد:** وضعیت زنده («خاموش»، «در انتظار شبکه»، «آماده»، «پورت اشغال است»)، کلید «اشتراک‌گذاری در این شبکه»، نشان «بدون نشتی»، ردیف‌های قابل کپی <bdi>SOCKS5 10810</bdi>، <bdi>HTTP 10811</bdi>، نشانی‌های دیگر رایانه، «کپی همهٔ مشخصات»، مراحل راه‌اندازی و نشانی بررسی.
* **همهٔ آداپتورهای واقعی:** اشتراک روی همهٔ نشانی‌های <bdi>Wi‑Fi</bdi> و <bdi>Ethernet</bdi> رایانه گوش می‌دهد (آداپتورهای مجازی و <bdi>Wi‑Fi Direct</bdi> کنار گذاشته می‌شوند) و هنگام اتصال، تغییر شبکه را دنبال می‌کند.
* **نام کاربری و رمز اختیاری:** مثل اندروید، به‌طور پیش‌فرض خاموش است. وقتی روشن باشد، <bdi>SOCKS5</bdi> (<bdi>RFC 1929</bdi>) و پراکسی <bdi>HTTP</bdi> (<bdi>Basic</bdi>) آن را می‌خواهند. رمزی قوی ساخته می‌شود؛ می‌توانید نام کاربری و رمز دلخواه (دست‌کم ۸ نویسه) بگذارید یا با «ساخت رمز جدید» آن را عوض کنید. هر دو با <bdi>DPAPI</bdi> رمز می‌شوند و هرگز در صفحه‌های اشتراک نمایش داده نمی‌شوند.
* **<span dir="ltr">`http://aether.check/`</span> از هر مسیر:** دستگاه مهمان از راه پراکسی <bdi>HTTP</bdi>، <bdi>SOCKS5</bdi> یا فایل <bdi>PAC</bdi> با باز کردن این نشانی می‌بیند محافظت می‌شود یا نه، از کدام مسیر وصل است و آی‌پی خروجی تونل چیست.
* **صفحهٔ راه‌اندازی:** نشانی <bdi>`http://<نشانی رایانه>:10811/`</bdi> راهنمای دوزبانه (فارسی و انگلیسی)، فایل <bdi>PAC</bdi> (<span dir="ltr">`/proxy.pac`</span> و <span dir="ltr">`/wpad.dat`</span>)، آزمون زندهٔ نشت <bdi>WebRTC</bdi> و قفل‌های یک‌کلیکی <bdi>WebRTC</bdi> برای <bdi>Windows</bdi>، <bdi>Firefox</bdi>، <bdi>macOS</bdi> و <bdi>Linux</bdi> را دارد. این صفحه‌ها هیچ چیزی از اینترنت بارگذاری نمی‌کنند.
* **نگهبان بدون نشتی:** دستگاه‌های مهمان به نشانی‌های خصوصی یا محلی شبکهٔ میزبان دسترسی ندارند، هیچ قاعدهٔ «مستقیم» (بای‌پس) نمی‌گیرند، سرآیندهای شناسایی‌کنندهٔ پراکسی حذف می‌شوند و <bdi>UDP</bdi> از راه <bdi>SOCKS5</bdi> فقط وقتی ارائه می‌شود که موتور بتواند آن را حمل کند.

### هسته، مسیریابی و تنظیمات (از پیش در ۱.۳.۰)

* **هستهٔ دست‌نخوردهٔ <bdi>Aether Core 2.4.0</bdi>:** همهٔ حالت‌های تور از <span dir="ltr">`tor.exe`</span> همراه برنامه استفاده می‌کنند و کاشی پروتکل به‌جای <bdi>SMART</bdi> عنوان <span dir="ltr">`Tor → Psiphon`</span> را نشان می‌دهد. فرزند سایفون از کامیت سازگار <bdi>CluvexStudio</bdi> ساخته می‌شود و سرورهای همراه را از راه <span dir="ltr">`AETHER_PSIPHON_SERVER_ENTRIES`</span> می‌گیرد.
* **<bdi>DNS</bdi> و مسیریابی:** «بای‌پس سایت‌های ایرانی» و «حذف تبلیغات و ردیاب‌ها» دو کلید اختیاری و مستقل‌اند، با فهرست‌های همراه و به‌روزرسانی هفتگی از داخل تونل. دامنه‌های ایرانیِ غیر از <span dir="ltr">`.ir`</span> پیش از مستقیم شدن با <bdi>DNS-over-HTTPS</bdi> از داخل تونل بررسی می‌شوند. در حالت‌های <span dir="ltr">`Aether → Psiphon`</span> و <span dir="ltr">`Tor → Psiphon`</span> قواعد در پل محلی اعمال می‌شوند.
* **سروری که کار می‌کند دیگر دور ریخته نمی‌شود:** برنامه به موتور می‌گفت سرورِ به‌خاطرسپرده را فقط در صورتی دوباره استفاده کن که سریع‌تر از حدود **۳۰۰ میلی‌ثانیه** جواب بدهد — و در شبکه‌های واقعی هیچ سروری این‌قدر سریع جواب نمی‌دهد. پس سرورِ سالم هر بار دور ریخته می‌شد و هر اتصال مجدد هزینهٔ یک جست‌وجوی کامل را می‌پرداخت. آن بررسی حالا **به‌طور پیش‌فرض خاموش** است، بنابراین سرورِ به‌خاطرسپرده‌ای که جواب می‌دهد همان‌طور که موتور عمل می‌کرد استفاده می‌شود. اگر دنبال سریع‌ترین سرور هستید، سوئیچ «فقط اندپوینت سریع را دوباره استفاده کن» زیر «ترابرد و ضد <bdi>DPI</bdi>» با محدودیت‌های واقعی فعال است (<bdi>2000/5000</bdi> میلی‌ثانیه مستقیم و <bdi>1200/3500</bdi> میلی‌ثانیه زنجیره‌ای).
* **تنظیم <bdi>ECH</bdi> خودتان:** اگر یک <bdi>ECHConfigList</bdi> دارید، می‌توانید زیر «ترابرد و ضد <bdi>DPI</bdi>» بچسبانیدش به‌جای اینکه برنامه خودش یکی بگیرد. نشانه‌گرفتن <bdi>ECH</bdi> به یک دامنهٔ دیگر (مانند <bdi>v2rayNG</bdi>) ممکن نیست چون موتور در آن‌جا دامنه نمی‌پذیرد.
* **<bdi>MTU</bdi> دلخواه:** در بازهٔ **۱۲۸۰ تا ۹۰۰۰**.
* **هوش مصنوعی و ظاهر:** مدل پیش‌فرض در صورت دسترسی <bdi>Gemini 3.1 Flash-Lite</bdi> است و سقف توکن فقط وقتی نمایش داده می‌شود که گوگل اعلامش کند. کارت اتصال وضعیت، آی‌پی، زمان و ترافیک را یک‌جا نشان می‌دهد و تنظیمات دارای کارت‌های گروه‌بندی‌شده و کاشی‌های افقی است.
* **حفظ بک‌اند انتخابی:** <bdi>Aether</bdi> فقط پیش‌فرض پروفایل تازه است و بستن و باز کردن برنامه انتخاب کاربر را عوض نمی‌کند.

### بسته‌ها

خروجی‌ها نصب‌کننده‌های <bdi>x64/x86</bdi> با پسوند <span dir="ltr">`.exe`</span> و بسته‌های پرتابل <span dir="ltr">`.zip`</span> به‌همراه <span dir="ltr">`SHA256SUMS.txt`</span> هستند؛ فایل <span dir="ltr">`.msi`</span> وجود ندارد. نسخه در همهٔ فایل‌های مشخصات <bdi>1.4.0</bdi> است و پیش‌بررسی <bdi>CI</bdi> این را کنترل می‌کند. رفتار واقعی تونل و شبکه همچنان باید روی ویندوز آزموده شود.

## دریافت نسخهٔ ویندوز

نام خروجی‌هایی که فرایند انتشار پروژه برای ویندوز در نظر گرفته است در جدول زیر آمده‌اند. برای موجودیِ واقعی فایل‌ها و بررسی هش، صفحهٔ [انتشارها](../../releases) را ببینید. در این مخزن خروجی <span dir="ltr">`.msi`</span> معرفی نشده است.

| نام فایل | کاربرد |
| :--- | :--- |
| `Aether-Setup-1.4.0-x64.exe` | نصب‌کنندهٔ ۶۴بیتی با قابلیت حذف |
| `Aether-Setup-1.4.0-x86.exe` | نصب‌کنندهٔ ۳۲بیتی با قابلیت حذف |
| `Aether-Portable-1.4.0-x64.zip` | نسخهٔ پرتابل ۶۴بیتی |
| `Aether-Portable-1.4.0-x86.zip` | نسخهٔ پرتابل ۳۲بیتی |
| `SHA256SUMS.txt` | هش‌های فایل‌های انتشار برای بررسی یکپارچگی |

پیش‌نیاز اعلام‌شدهٔ پروژه ویندوز ۱۰ نسخهٔ ۱۸۰۹ یا جدیدتر است. برای ایجاد آداپتور و اعمال محافظت‌های شبکه، برنامه دسترسی مدیر درخواست می‌کند. پیش از استفاده از قابلیت‌های حساس، از صفحهٔ انتشارِ موردنظر، درستی هش فایل دریافتی را بررسی کنید.

### به‌روزرسانی مخزنی که هنوز روی ۱.۲.۵ است

فایل ZIP را باز کنید، وارد پوشهٔ <span dir="ltr">`Aether_Windows_V1.4.0`</span> شوید، همهٔ محتوایش را انتخاب و در پوشهٔ مخزن کپی کنید و وقتی <bdi>Explorer</bdi> پرسید، گزینهٔ **Replace the files in the destination** را بزنید. سپس در <bdi>GitHub Desktop</bdi> تغییرات را **Commit** و **Push** کنید. فایل‌های اضافیِ ۱.۲.۵ اگر در مخزن بمانند مشکلی نیست: فرآیند <bdi>CI</bdi> پیش از هر بررسی و بیلد آن‌ها را خودکار پاک می‌کند (<span dir="ltr">`scripts/clean-legacy-1.2.5.py`</span>). پنج لینک <span dir="ltr">`quiche/fuzz/mayhem/*/testsuite`</span> عمداً در ZIP نیستند چون در ۱.۲.۵ پوشه‌اند و سیستم‌عامل نمی‌تواند فایل را جای پوشه بگذارد؛ این‌ها فقط لینک تست fuzz هستند و در بیلد استفاده نمی‌شوند.
