# گزارش اصلاحات UI/UX — Aether Windows 1.4.0

## وضعیت واقعی تحویل

این بسته شامل **سورس اصلاح‌شده، رابط وب بیلدشده و شواهد تست رابط** است؛ **بیلد نهایی ویندوز یا فایل EXE جدید ندارد**. درخواست تحویل بیلد ویندوزِ تست‌شده در این محیط تکمیل نشده است.

محیط اجرا Linux x86_64 با Node 24 و Chromium است. اجرای `npm run build` در مرحله `cargo metadata` به علت نصب‌نبودن Cargo متوقف شد. MSVC/Windows SDK، محیط اجرای Windows/WebView2 و payload نهایی موتورهای ویندوز در این اجرا آماده نیستند. تست کامپایل و اجرای Rust/DPAPI و تست نصب یا اتصال واقعی تونل انجام نشده‌اند. سبزبودن تست‌های وب به معنی تأیید این موارد یا تضمین نبود تمام باگ‌ها نیست.

اسکرین‌شات‌ها از **سورس واقعی رابط در Chromium** با **داده‌های آزمایشی و IPC جایگزین‌شده در تست** گرفته شده‌اند؛ تصویرسازی مجدد یا ماکاپ نیستند، اما تصویر اجرای باینری ویندوز هم نیستند. قبل و بعد از یک داده آزمایشی مشترک استفاده می‌کنند؛ دقیقاً داده‌های سرورهای موجود در تصاویر کاربر نیستند. تمام نشانی‌های `example.invalid` آزمایشی‌اند و اتصال شبکه‌ای واقعی به VPN انجام نشده است.

## معنای حذف مستقل تب

- حذف تب، مانند رفتار قبلی تب دستی، **کانفیگ‌ها را حذف نمی‌کند**؛ آن‌ها در «همه» باقی می‌مانند.
- «همه» تب دائمی است و دکمه × ندارد؛ فرمان حذف آن نیز در بک‌اند بی‌اثر است.
- تب‌های فرمت و اشتراک بعد از بسته‌شدن با تغییر انتخاب یا دریافت state دوباره ظاهر نمی‌شوند؛ شناسه آن‌ها در `hiddenTabs` نگهداری می‌شود.
- حذف تب اشتراک، داده و اعتبارنامه اشتراک را پاک نمی‌کند و روی اشتراک دیگر اثر ندارد.
- تب‌های اشتراک، کانفیگ‌ها را بر اساس شناسه‌های واقعی همان اشتراک فیلتر می‌کنند؛ تب دستی و فرمت مستقل‌اند.
- به‌روزرسانی اشتراک برای تب‌های باز از پنجره ویرایش تب (مداد) قابل دسترسی است؛ نوار پایین برنگشته است.
- حذف گروه دستی فقط عضویت گروه را برمی‌دارد. تب‌های خودکار بسته‌شده تا پاک‌سازی کامل داده‌ها بسته می‌مانند؛ رابط بازیابی جداگانه به این درخواست اضافه نشده است.
- فرمت ذخیره‌سازی با داده‌های قبلی سازگار است: نبود `hiddenTabs` به فهرست خالی تبدیل می‌شود؛ نسخه برنامه یا موتور برای این قابلیت تغییر نکرده است.

| `bash scripts/preflight-local.sh` | موفق با SKIP صریح تست‌های Cargo؛ خروجی کامل پیوست است |
| `python3 scripts/check-rust-parses.py` | بررسی ساختاری ۱۰۳ فایل Rust موفق؛ این ابزار کامپایلر نیست |
| دو تست جدید `custom/store.rs` | برای ماندگاری بسته‌شدن تب و حفظ کانفیگ/اشتراک نوشته شدند؛ اجرا نشده‌اند چون Cargo موجود نیست |
| `npm run build` | ناموفق به علت نبود Cargo؛ هیچ EXE جدید ساخته نشده است |

تست reload در مرورگر، لایه نمایشی را با ذخیره‌سازی آزمایشی تست بررسی می‌کند؛ جایگزین اثبات ماندگاری واقعی DPAPI ویندوز نیست. تست‌ها شبکه، پینگ واقعی، نصب، WebView2 و خود موتور تونل را پوشش نمی‌دهند.

## نسخه‌ها

`package.json`، ریشه `package-lock.json`، `src-tauri/Cargo.toml`، ورودی برنامه در `src-tauri/Cargo.lock`، `tauri.conf.json` و مقدار نسخه نصب‌کننده همگی **1.4.0** باقی مانده‌اند. نسخه عددی مانيفست Windows طبق قالب چهارقسمتی موجود **1.4.0.0** است و تغییر نکرده. نسخه هسته موجود **2.4.0** و نسخه وابستگی‌ها دست‌نخورده‌اند؛ آن‌ها نسخه برنامه نیستند. فایل `Reports/version-check.json` بررسی ماشینی را ثبت می‌کند.

## شواهد تصویری

در پوشه `Screenshots`، تصاویر کامل قبل و بعد فارسی در اندازه 390×820 و هشت تصویر کنارهم برای a1 تا a7 (a6 دو تصویر) وجود دارند. دو تصویر اضافه، وضعیت تب بعد از درگ و تأیید حذف را نشان می‌دهند. نمای a1 در حداقل اندازه 360×720 نیز پیوست شده است. فایل‌های JSON نتیجه چهار حالت خودکار را ثبت می‌کنند. در تنظیمات مرورگر تست گزینه پیش‌فرض `--hide-scrollbars` غیرفعال شده تا خود اسکرول‌بار در تصاویر دیده شود.

## تکمیل بیلد ویندوز

1. سورس را در محیط بیلد ویندوز مجهز به Rust MSVC، Visual Studio C++/Windows SDK و Node سازگار یا در مخزن GitHub خود قرار دهید.
2. `npm ci`، `npm test` و `npm run test:uiux` را اجرا کنید. تست تصویر به Chrome/Chromium نیاز دارد؛ متغیر `CHROME` می‌تواند مسیر آن را تعیین کند.
3. برای آماده‌سازی موتور، Wintun، Tor/Psiphon و بسته نصب از **گردش‌کار موجود `Build Windows`** و اسکریپت‌های پروژه استفاده کنید؛ اجرای تنها `tauri build` بدون payloadها کافی نیست. گزینه `core_sync` روی `off` بماند تا هسته موجود بی‌درخواست عوض نشود.
4. در preflight گردش‌کار، تست جدید UI/UX اجرا و تصاویر با نام `Aether-UIUX-1.4.0-Web-QA` ذخیره می‌شوند. در این جلسه هیچ گردش‌کار GitHub اجرا یا انتشار release انجام نشده است.
5. پس از ساخت، باینری x64/x86، نصب‌کننده و برنامه portable را واقعاً روی Windows/WebView2 اجرا کنید؛ ذخیره/بازگشایی تب‌ها با DPAPI، همه دیالوگ‌ها، درگ/اسکرول، نسخه About، اتصال واقعی و عدم برگشت تب بسته‌شده پس از راه‌اندازی مجدد را کنترل و تصویر بگیرید.
6. فقط پس از آن می‌توان EXE/portable را همراه شواهد بومی به‌عنوان تحویل نهایی ویندوز بسته‌بندی کرد.

لاگ‌ها و گزارش‌های validation موجود در سورس ورودی، تاریخی‌اند؛ شواهد همین اصلاحات در پوشه `Reports` بسته تحویل و این سند مشخص شده‌اند.
